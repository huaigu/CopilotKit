## 目标与范围

在 CopilotKit 中接入真正的 Pi Agent：由 Pi 负责模型调用、工具执行、Skills、上下文压缩和会话；CopilotKit 负责聊天、工具展示及页面交互。运行链路使用 Node.js / TypeScript，不依赖 LangGraph 或 FastAPI 服务。

首版交付一个可复用的服务端适配包和一个可运行的 React 示例，验证文本流、后端工具、会话恢复、取消、前端工具回传、人工确认及最小共享状态。示例同时验证中文和英文。

本轮范围不包括 DSH、多个 Harness 的调度平台、完整 Skills 管理界面、MCP 全生态兼容、任意代码生成 UI、多实例部署和生产发布。保留已有集成；新增模块不改变其他 Agent 的默认行为。

## 接入设计

使用进程内 Pi SDK，注册一个实现 AG-UI `AbstractAgent` 的 `PiAgent`。浏览器仍通过 `runtimeUrl` 访问 CopilotRuntime；Pi、模型凭据、会话文件和工具都在服务端。

| 拟新增模块 | 职责 |
| --- | --- |
| `packages/pi-agent/` | 独立适配包，拟用名称 `@copilotkit/pi-agent`；首版设为 private，不发布 npm |
| `src/pi-agent.ts` | 接收 AG-UI 输入、订阅 Pi 事件、实现 `run` / `clone` 与取消衔接 |
| `src/session-store.ts` | 维护线程到 Pi 会话的映射、串行执行和资源释放 |
| `src/event-mapper.ts` | 文本、工具、运行状态与共享状态的事件转换 |
| `src/frontend-tool-bridge.ts` | 前端工具注册、等待结果、校验回传和恢复 Pi 执行 |
| `examples/v2/react/pi-agent/` | 最小 Next.js / React 示例，使用 Node Runtime 路由、v2 聊天组件与少量业务交互 |

模块名称可随代码组织调整，职责和验收要求保持不变。Pi 依赖只进入服务端适配包，避免把 Node.js / 文件系统依赖引入浏览器构建或所有 Runtime 用户的依赖树。

CopilotRuntime 首版复用 `InMemoryAgentRunner` 承载运行、流式转发与停止；Pi `SessionManager` 是模型上下文和已完成对话的持久化来源。前端历史投影从 Pi 会话生成。阶段 0 必须验证 Runtime 的历史、重连与停止行为，再决定是否需要示例内一个很小的历史读取路由，不为首版另建通用 Runner 或数据库。

## 必须明确的行为

### 1. 事件与运行生命周期

- 先建立订阅，再启动 `session.prompt()`，保证首个 token 不丢失。
- 将 Pi 的文字增量转换为 AG-UI 文本事件；消息 ID、工具调用 ID 在一次运行及恢复过程中保持一致。
- 工具参数与执行结果分开处理。`TOOL_CALL_END` 表示参数发送结束，不能当成工具执行成功。
- 正常运行以 `prompt()` 完成或 `agent_settled` 为完成依据。Pi 的 `agent_end` 后可能还有自动恢复或排队任务，不能直接据此关闭整个用户任务。
- 对正常完成、错误、用户停止、前端工具交接分别定义终态；按 AG-UI 1.0.2 验证合法事件顺序，防止重复结束和结束后继续输出。
- `clone()` 保留服务端配置和会话管理器引用，保留父类 middleware；每个 run 的订阅、输出状态和 ID 单独管理。

### 2. 会话、历史与资源

- 一个线程对应一个 Pi 会话，不使用全局共享的 `AgentSession`。同线程的普通运行串行化；前端工具结果走恢复路径。
- 新用户消息按 ID 去重后进入 Pi。已有会话不反复灌入整个浏览器历史；工具结果只交给匹配的等待项，不能转换成新的用户提示。
- Pi 自行完成上下文压缩；UI 展示历史与模型压缩后的上下文分开，不能将 UI 旧历史重新导入以覆盖压缩结果。
- 支持刷新后继续同一线程，以及单实例重启后恢复已完成对话。需持久化最小线程映射，具体文件结构在阶段 0 核定。
- 已失去执行进程的未完成工具调用显示为中断；首版不承诺跨进程续接未完成的 Promise，也不自动重放可能有副作用的工具。
- 线程退出或空闲回收时释放订阅、等待项与 Session；停止操作调用 Pi 的取消接口并处理正在等待的前端工具。
- 示例定位为本地单用户验证。适配器预留由服务端提供的用户作用域；若上线多用户，运行、历史、重连和停止都要检查线程归属。`cwd` 是工作目录，不等同于安全沙箱。

### 3. 前端工具、确认与共享状态

这是首版的关键验证项，不能仅靠后端工具日志代替。

- 接收 `RunAgentInput.tools`，将受支持的 JSON Schema 转成 Pi 工具定义；不支持的 schema 明确报错。
- 后端工具继续由 Pi 执行；前端工具交给 CopilotKit 在浏览器执行，或等待用户填写 / 确认。
- 前端交接时，结束当前传输所需的 AG-UI run，但保留等待结果的 Pi 任务。恢复请求按线程和 `toolCallId` 找回等待项，注入结果后继续原来的 Pi 执行。
- 区分传输订阅释放与用户主动取消，避免普通流结束误杀正在等待用户的 Pi 任务。
- 重复、过期、其他线程的回传不触发二次执行；拒绝确认、取消和超时也有明确的工具结果与终态。
- 用一个小型对象验证共享状态：用户在页面修改数值，Pi 下一轮能读取；Pi 调用显式状态工具后，页面收到 `STATE_SNAPSHOT` 并更新。首版不做通用双向复杂合并。
- 阶段 0 用真实 CopilotKit 客户端验证上述交接方式。若当前 API 无法支持，先修订接法和计划，不用拼接文本假装完成工具续跑。

### 4. Skills 与配置

- 复用 Pi 的 `DefaultResourceLoader`，通过明确的工作目录及受控资源目录加载 Skills；使用一个无外部副作用的示例 Skill 验证发现、读取与使用。
- 不自动继承服务端宿主机全部个人插件、凭据和工作目录。可执行扩展需由服务端显式配置。
- 模型、provider、API base URL 与凭据由服务端配置；示例给出无密钥的环境变量模板和启动说明。
- 默认示例只启用演示所需工具。文件读写 / shell 等编码工具作为显式配置项，文档解释其运行位置和权限。
- 第一版不额外实现 `@skill` 选择器、插件商店或模型管理后台。

## 验收清单

| 场景 | 通过标准 |
| --- | --- |
| 中英文流式对话 | 首段文字实时显示；正文无重复、丢字或乱码；前端能正确结束 loading |
| 多轮上下文 | 第二轮正确使用第一轮信息，模型上下文中用户消息不重复 |
| 后端工具 | 显示名称、参数和结果；模型基于真实工具结果继续回答；失败能被识别 |
| 前端工具 | Agent 改变一个页面状态，拿到浏览器返回值后继续；没有把浏览器动作在后端假执行 |
| 人工确认 | 确认后执行一次；拒绝后不执行；等待时可取消；重复回传不重复执行 |
| 共享状态 | 页面修改能被 Pi 读取；Pi 的显式状态更新能反映到页面 |
| Skill | 指定测试 Skill 被 Pi 发现并实际读取 / 使用，有工具或资源访问记录支持 |
| 停止与异常 | 停止后 Pi 不再继续执行；连接和等待项可释放；同一线程之后能重新提问 |
| 会话恢复 | 刷新不丢当前线程；服务重启后恢复已完成历史；未完成任务明确显示中断 |
| 两线程隔离 | 交错运行两条对话，消息、状态和工具结果不交叉 |
| 版本与构建 | Node.js 22.19+；AG-UI 依赖一致；类型检查、构建、针对性测试和相关回归通过 |
| 示例界面 | 桌面和窄屏下聊天、工具卡片、确认控件、错误及停止状态可读、可操作 |

自动化测试分两层：事件投影的确定性单元测试，以及实际 Pi SDK / CopilotKit 客户端与模型桩的集成测试。仅模拟适配器返回字符串不算 SDK 集成通过。

真实模型彩排至少覆盖中英文多轮、一个后端工具、一个前端工具、确认 / 拒绝、Skill 使用和停止。记录模型标识、版本、运行步骤与结果；未配置真实模型时明确记为未验证，不把模拟结果当成彩排成功。

通过 Nx 运行新适配包和示例的 `test`、`check-types`、`build` 等实际注册目标；读取各目录约定后执行必要的 Runtime / 前端回归。运行 `git diff --check` 并检查依赖和改动范围。计划提交阶段只检查文档与分支，不安装整仓依赖或声称功能测试通过。

## 风险与实施边界

1. Pi 的 SDK、资源加载和工具 schema 以锁定版本的类型及行为为准；不把社区示例当作兼容性保证。
2. 前端工具交接跨越两个 AG-UI run，却可能属于同一次 Pi `prompt()`；必须通过阶段 0 的验证后再扩展功能。
3. Runtime 运行事件与 Pi 持久化上下文有不同用途；必须明确历史投影与恢复路径，避免两个组件互相覆盖历史。
4. 首版使用持久 Node.js 进程和本地会话目录；不承诺 Edge Runtime、无状态函数或多实例的会话一致性。

用户本次要求先制定计划。实现、部署、合并和 npm 发布均尚未进行。
